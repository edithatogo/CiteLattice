# Scientific coverage status

Machine-readable [outcome inventory](../contracts/methods/catalog.json) is **not** an executable method library, and cannot be used to claim bibliometrix or PyBibX parity. It explicitly distinguishes unfilled methodological references, formula, denominator, counting and numerical oracle.

Principal baselines: bibliometrix/Biblioshiny production, citation, collaboration, intellectual/social/conceptual structures and thematic evolution; PyBibX bibliometric and scientometric portfolio, main-path and temporal graph explorer; Dimensions linked funding, trials, patents, datasets and policy.

Low-hanging priority: descriptive annual/venue/author profile; local/global citation rates; h/g/e/m/i10; Lotka/Bradford/Zipf; co-authorship/co-word/co-citation/bibliographic coupling; centralities; RPYS/main paths and thematic evolution. Beyond basic indicators: coverage-aware normalisation, partial-observation bounds, research-system links, uncertainty-sensitive maps, source/version-aware temporal dynamics.

Every outcome requires a named scientific definition, source reference, suitable input fields, explicit population and citation universe, fractional/full counting, missingness and edge-case policy, independent known-answer fixtures, method version, numerical tolerance, and a clear implementation/evidence state.

No threshold-based sleeping beauty category without specified criterion; no FCR/RCR clone computed from an unrepresentative corpus.
